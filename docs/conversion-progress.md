# 付费转化改造交接（2026-10-07）

## 目标与范围

把成功体验后的用户接到付费制作和交付：结果页入口 → 选包 → 登录续购 → Stripe → 服务端确认到账 → 原照片高清制作/恢复已上传照片。保持 $4.99/10、$9.99/25、$19.99/60 一次性积分包、积分一年有效期、免费每日一次；没有上线单张 $1.99 定价实验。

## 已完成

1. **登录续购**：选定套餐、原任务、语言、工具路径进入受限上下文；登录回调只自动续购一次，取消结账不会重开。手机端已选套餐优先显示。
2. **结果页付费入口**：所有可升级的免费结果（含匿名结果）展示真实权益。付费账户明确点击一次 1 积分高清重制；原预览保留。专业版显示其已有权益，不误报按次扣费。
3. **高清交付**：复制原图到独立对象，复用现有队列、模型和原子扣减。任务固定生成品质，不因账号后来充值而改变旧结果的品质标记。重制永久幂等；网络丢响应、最后一积分已用完后，可找回已扣费任务而无需再次买包。
4. **到账确认**：仅当 Stripe 显示 paid 且数据库持久到账回执存在时展示付款确认；不相信 success=true。积分、用户等级和回执单 Lua 事务，重复/并发 webhook 不重复加积分。checkout 事件不使用可能提前锁死的外层 claim。
5. **上传承接**：额度耗尽显示购包入口；当前浏览器会话中保留已上传对象引用 24 小时，按账号、工具路径、处理类型隔离。付款后返回原工具，用户明确点击继续才消费额度。不是永久云草稿，也不跨浏览器恢复。
6. **并发保护**：每日免费重置、过期积分清理改为读取当前值的 Lua；登录初始化 SET NX。避免与充值交错而覆盖已到账积分。
7. **统计**：升级曝光/点击、登录续购、结账、可信 purchase、付费结果浏览；服务端记录付款与完成交付。管理面板新增近 14 天五项统计与刷新，失败时显示不可用，不伪装为 0。
8. **多语言与布局**：新增面向客户的文字包含英/中/西/日四语言；后台文字保持中文。按钮最小 44–48px；统计卡 gap 16px、内边距 16px，手机无横向溢出。

## 统计口径

- `purchase` 仅由已认证的 checkout/status 返回 fulfilled 后发送；金额以真实回执为准，交易 ID 为 SHA-256 摘要，不发送原始 Checkout ID、邮箱、照片 key、taskId。页面端上报仍可能受广告拦截或用户不返回影响。
- 服务端 `conversion:YYYY-MM-DD` 按 UTC 自然日：`purchases`、`revenue_minor_usd`、`generations_completed`、`paid_generations_completed`、`hd_remakes_completed`。400 天保留；任务完成与付费回执分别去重。收款未减退款，不含订阅续费。
- 管理接口：`GET /api/internal/admin/conversions?days=14`，沿用管理员 cookie / admin key；最多 90 天。没有公开业务或客户数据。
- 任务完成数并非独立用户数，更不能作为付费转化率的直接分母。GA 漏斗应看成功结果用户 → 升级点击 → 结账 → 真实付款；当前后台卡供付款/交付核对。
- 统计自本次上线开始；未用旧任务反推历史曝光或补造付款数据。
